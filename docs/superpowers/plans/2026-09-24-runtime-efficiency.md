# Runtime efficiency and Strands experiment

Goal: reduce repeated evidence tokens, add an opt-in Strands worker, and compare runtimes without changing the production default.

Architecture: keep FastAPI, PostgreSQL, Celery, scoped MCP tools, spending reservations, tool limits/recovery, and durable UI events. Share those controls with an optional Strands harness through the existing LangChain provider models. Reject unsupported experimental configurations before execution. Preserve complete immutable evidence in existing storage; previews are projections only.

Tech stack: Python 3.12, Deep Agents 0.7.16, Strands Harness 0.1.2 / Agents 1.57.0, LangChain, pytest. Product/tech/design specifications remain authoritative. User approved this experiment on 2026-09-24.

Global constraints: preserve unrelated working changes; do not commit or deploy. No real contacts or outbound actions. No paid calls without a new explicit spending cap. Deep Agents remains the default. Synthetic comparisons do not establish real token or quality savings. No shell/filesystem/memory/subagent capabilities in Strands. Single-agent experimental runs only; durable questions and recovery of an interrupted Strands run must fail closed until implemented. All model calls, including compaction, must share accounting and spending controls.
