# Command Center Companion

Start the API on localhost:8000 and web app on localhost:3001. In Chrome's Extensions page, enable Developer mode and Load unpacked → this directory. Open the workspace's Browser companion page, create a pairing code, and paste it into the extension popup.

Open an application form and click **Share this form**. The popup can prepare reviewed profile answers, keep local edits across popup closes, queue grounded draft generation, pin an exact resume version, and create a fill proposal. Choose every resume upload control explicitly. Click **Check fill proposals**, review every answer and file, then apply. Pairing codes are one-use and expire in five minutes; device credentials can be revoked in the workspace. Extension storage is restricted to trusted extension contexts and holds the revocable device credential plus the current local review draft.

The companion supports native text/email/telephone/URL inputs, textareas, single selects, radio groups, checkboxes, and explicitly selected file inputs in the top frame. Associated visually hidden file inputs are supported; custom widgets, rich text editors, dates, multi-selects, inaccessible controls, and sensitive password/payment/SSN fields are excluded or disclosed as unsupported. It records only whether an existing value is present, never that value. Existing and late local edits are preserved unless replacement is explicit. Exact resume bytes are downloaded only after claim, verified by size and SHA-256 in the popup and content script, and attached through `File` and `DataTransfer`.

The companion never clicks Next or Submit. A proposal is tied to the exact live URL and captured control structure; stale pages require a fresh share. Each field reports filled, uploaded, preserved, unsupported, rejected, failed, or outcome unknown. A claimed command is recorded locally before apply and never replayed automatically, including when the page or result endpoint becomes unavailable.

Synthetic browser coverage lives at `/fixtures/application.html` plus grouped-control, upload, custom-widget, and dynamic-page fixtures. All fixture data is fictional and no signed-in employer form is tested. Remote API deployments need an explicit host-permission and HTTPS configuration change.

HTTP payloads and the versioned popup/content messages are defined in `apps/api/src/command_center/api/browser_contracts.py`. Run `make contracts` after schema changes; this generates Next.js types and the bundled `contracts.js` runtime validators. Both sides reject incompatible/malformed messages before filling. Validators are compiled ahead of time for Manifest V3 (no eval or remote code). Reload the unpacked extension after updates. `make contracts-check` catches drift and `make test-browser` starts its own synthetic fixture server on port 4319.
