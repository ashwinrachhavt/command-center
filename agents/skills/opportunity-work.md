# Finish focused opportunity work

Apply this skill only to job-search, application, outreach and interview-preparation requests. The supervisor still handles general workspace work. Optimize for a useful completed work product and a clear next action, using existing leads before discovering more.

## Select the work

Honor the user's current selection and requested mode first: organize, research, draft an application, draft outreach, or practice. An explicitly prioritized interview takes precedence over routine pipeline work. Organizing preparation material does not authorize starting a mock interview.

For a requested opportunity shortlist, use this confirmed priority order when the input establishes the tier: explicitly selected by the user, deeply researched in a Codex session, imported from Notion, then general research. Explicit selection promotes any source; retain its original provenance separately. Do not infer a tier from note length, an MCP audit, generic urgency or missing metadata. Show unknown provenance separately instead of quietly assigning it the lowest tier. Within a tier, honor an explicit deadline or user ordering; otherwise retain the supplied order and state that no tie-break preference is set. Do not change stored urgency to encode source priority.

A lead explicitly documented as manually created by the user counts as personally chosen. An integration-created record does not establish that choice.

Use the requested batch size. When it is unset, propose the next useful item and leave batch size open; do not invent a daily quota or stop useful work to ask for one. Apply hard role, location, eligibility or compensation filters only when explicitly supplied or present as active reviewed preferences. Unknown eligibility remains a gap, not a rejection or a qualification. Do not research additional leads unless requested or necessary to resolve the chosen work.

## Define completion before drafting

For each selected lead, identify the intended result, relevant record/source references, what already happened and the next action. Reuse existing research and inspect relevant saved work so an already-sent reply, completed application or human draft is not duplicated. A stale or partial observation does not establish current external state.

Pass specialists the user's mode, selected evidence, approved facts, relationship/channel, preserved human content and unresolved inputs. Ask for the finished draft or dossier, its actual save reference and remaining gaps. Research should answer a specific missing question; stop once the requested work can be supported.

Return a compact work list: lead, why it is next, completed output or honest partial result, one next action and any blocking fact. Distinguish ready for review, needs input and awaiting a response. These labels describe the work; do not claim persisted status changes without successful tool results. Keep follow-up timing unset unless the user supplied it or an active reviewed policy applies. Create a follow-up task only when requested and after checking for an existing one.

Agents prepare; the user approves messages and applications, including follow-ups. Preserve the existing manual Next/Submit and exact reviewed-action contracts. Tool availability, scoped permissions and receipts determine what actually happened across connected apps. Desired future integrations are not available tools.
